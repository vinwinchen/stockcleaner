# StockCleaner

**金融/股票数据清洗工具 —— 把"看起来是数值"的单元格变成真正的数值，把"看起来是日期"的单元格变成统一的日期，全程不静默丢失任何信息。**

## 这是什么

从券商软件、Excel 导出的金融数据有一个共同的毛病：**整张表看起来是表格，实际上大半是文本**。
股票代码 `000001` 被吃成 `1`，金额 `1,234.5` 排不了序，日期 `2023年1月1日` 和 `2023-01-01`
混在一列，全角数字 `２３４` 混在半角里 —— 常规解法是"导入时让 pandas 自己猜"，
而猜错的代价是数据被静默改写或丢弃，你毫不知情。

StockCleaner 把这条路反过来走：**逐值解析，失败保留原值，每一步改动都留痕**。
它不是"再写一个 read_excel"，而是一套把"永不静默丢数据"当作硬约束的清洗内核，
外加一个"先看见、再动手"的桌面界面：

- **先预览后清洗**：规则一改立即看到每一列 `原值 → 结果` 的逐格对照，全程只读不落盘；
- **不确定就保留**：欧式小数、百分比、畸形千分位这类有歧义的写法，宁可保留原文本也不猜；
- **界面报的数必须是内核真的数**：预览与正式运行走同一条代码路径，报告数字可对账。

清洗内核 `cleaner_core.py` 是唯一实现，无 GUI 依赖、可独立测试；界面只是编排层。

## 洗之前 → 洗之后

| 原始值 | 清洗后 | 说明 |
|---|---|---|
| `000001` / `00700` / `000001.0` | 原样保留（文本） | 识别为标识符列，前导零不能丢 |
| `1,234.5` | `1234.5` | 千分位 |
| `¥1,234` / `1,234元` | `1234` | 货币符号、单位后缀 |
| `(1,234)` | `-1234` | 会计负数 |
| `１２３` | `123` | 全角数字在数值化内建翻译；文本列的全角转半角通道默认关，可开启，可按列豁免 |
| `1.5亿` / `3千万` / `1.5万亿` | `150000000` / `30000000` / `1500000000000` | 中文单位换算，全程整数运算 |
| `1.005万` | `10050` | 精确整数缩放，不是 `10049.999999999998` |
| `2023年1月1日` / `2023.01.01` | `2023-01-01` | 日期按内容识别，不依赖列名（`２０２３．１．８` 需开启全角转半角） |
| `2023-01-05 14:30:00` | `2023-01-05` + 新列 `列名_时间`（`14:30:00`） | 时间分量拆列保留，不截成日期 |
| `600519.0` | `600519` | 纯整数全程精确，无 `x.0` 表示漂移 |
| `N/A` / `NULL` | 原样保留 | 不吃 pandas 缺失值名单里的文本 |
| `1.234,5`（欧式小数）/ `1,23`（畸形分组）/ `12.5%` | **保留原值 + 警告** | 有歧义的写法不猜 |

## 核心特性

**读得进来**
- 支持 `.csv` `.tsv` `.txt` `.xlsx` `.xls` `.xlsm`；后缀不对但内容是文本表格的（`.dat` `.log`、无后缀）按文本猜读并留警告，含 NUL 的真二进制拒读。**扫描文件夹、原生对话框、粘贴路径、拖拽四条输入通道共用这一套判据**，不会出现"拖进来能洗、粘贴进来没反应"。
- **格式按文件头判定，不按后缀**：`.xlsx` 里装的其实是 CSV/TXT（券商软件常见）照常读成表格并留警告；反过来，改名成 `.csv` 的真 xlsx/xls 也按 Excel 读。不用先手动改后缀。
- 编码探测：BOM（utf-8 / UTF-16）+ 严格解码顺序 utf-8 → gb18030 → big5，兜底解码一律写进警告。
- 分隔符按"能不能把每行切成同样多列"打分（Tab/逗号/分号/竖线），引号里的字符不算票。
- 读取阶段零破坏：`dtype=object` 文本保真 + `keep_default_na=False`，字段数与表头不一致的行显式修复，绝不让 pandas 静默当索引、丢列、吃文本。
- Excel 读取可选 Rust 引擎 [python-calamine](https://github.com/dimastbk/python-calamine)（快 4-5 倍，需配 `dtype=object` 保住前导零）；没装或读不动就按容器回落（xlsx/xlsm → openpyxl，xls → xlrd）。

**洗得干净**
- 智能数值化、中文单位换算（整数运算）、四种日期写法统一、全角转半角、指定列/全表去字符、行裁剪、删除全空行/列。
- 逐列保护：任意一列可标记"不参与清洗"，保护列不进任何通道，"报告说改了 N 格"与净改动始终一致。
- 带时间分量的列拆成日期 + `列名_时间`，不把 `14:30` 与 `09:15` 截成同一个日期。
- 超过 float64 精度界的整数全程精确；xlsx 里 `|int| ≥ 2^53` 的格子按文本写出，不做舍入。

**看得见（界面不是换个皮肤）**
- **列检视**：每列给出逐格 `原值 → 结果` 对照、改动格数、识别类型（标识符/数值/日期/文本/新增列），按索引配对、行号是原文件位置，删过一行也不串位。
- **数据差异**：只读差异矩阵，被改写的格子划线显示原值，坏行并回了哪个字段、全角日期为什么没动，直接看得见。
- **运行报告**：逐文件的各类改动计数、标识符列、时间拆列、写法碰撞、警告、输出路径，可复制成文本。
- **输入三通道**：原生对话框 / 拖拽 / 粘贴路径；进度走 SSE（带 seq、服务端缓冲、断线重连回放最近 1024 条并有缺口标记）。
- **输出格式可选**：跟随输入 / xlsx / csv / 两种都写；扩展名永远与真实内容一致（跟随的是文件真实格式，不是后缀）。

**不重复吃进自己的输出**
- 默认输出到输入目录下的 `cleaned/` 子目录，并在输出目录写 `_stockcleaner_manifest.json` 登记真实产出；扫描时按"输出子树 + 登记清单"精确排除，不靠猜文件名。登记不可用时宁可多跑一次，也不静默漏文件。

# 使用说明书

> 快速路径：**把文件拖进来 → 选中一个文件 → 看右侧「原值 → 结果」→ 确认无误 → 点「开始清洗」**。
> 原始文件永远不被改写，结果写到输出目录下的 `xxx_cleaned` 文件。预览只读，不碰原始数据。
> 后缀写错也没关系（`.xlsx` 里其实是 CSV 之类），格式按文件头认，详见「后缀写错不用改」。

## 安装与启动

要求 Python ≥ 3.11。

```bash
cd webapp
uv venv && uv pip install -r requirements.txt      # 或 pip install -r requirements.txt
cd frontend && npm install && npm run build        # 产出 dist/
cd .. && python run.py                             # 起桌面窗口
```

不想看到终端窗口就用 `pythonw run.py`（同一个入口，只是没有控制台）。`samples/` 里有现成的演示数据（含 601 行"一份数据踩遍全部清洗路径"的全功能验证样例），进来就能试。

其他模式：

```bash
python run.py --no-shell              # 不起窗口, 用系统浏览器
python run.py --dev                   # 加载 vite dev server (需先在 frontend/ npm run dev)
python run.py --port 8720 --no-shell  # 固定端口, 便于自测与代理
```

环境变量：

| 变量 | 作用 |
|---|---|
| `SC_THEME=dark\|light` | 钉死默认主题（不跟随系统），打包成 exe 或做外观预设时用 |
| `SC_EXCEL_ENGINE=openpyxl\|xlrd\|calamine` | 钉死 Excel 读取引擎，既是兜底也是 A/B 计时对照组 |
| `SC_DEBUG=1` | `run.py` 带 devtools 启动 |

依赖说明：`python-calamine` 是非必需项，装了就优先用、没装按容器回落（xlsx/xlsm → openpyxl，xls → xlrd），功能不受影响。
`xlsxwriter` 实测过但**没有**采用：写 20 万行它 17.4s、openpyxl 16.7s，"换 xlsxwriter 提速"在这个量级上不成立。

**运行发布版 exe**：解压 `StockCleaner-2.2.5-win64.zip`，双击 `StockCleaner.exe`。首次启动可能被 Windows SmartScreen 拦一下，点「更多信息 → 仍要运行」即可（未签名程序的正常提示）。

> 服务只监听回环地址（`127.0.0.1`），并校验 Host 与 Origin 防 DNS rebinding；但它**不设鉴权**，本机其他程序可以调用。这是单用户桌面工具的残余风险，别把它当安全边界。

## 标准操作流程

1. **加入文件**（三种方式任选，详见下一节）：
   - 点「选择文件」多选，或点文件夹图标**递归扫描整个目录**；
   - 直接把文件从资源管理器**拖进左栏**；
   - 复制绝对路径，**粘贴**到左栏底部输入框（多个用 `|` 分隔），回车加入。
2. **点选一个文件**（队列里的每一行）。右侧立即出现该文件的干跑预览。
3. **调整清洗规则**（左栏下半）。规则一改自动重算预览（约 300ms 防抖），顶部会短暂显示「规则已改，正在重算」。
4. **核对**：「列检视」看每列改动格数与逐格对照；「数据差异」看前 60 行 × 前 24 列的整表差异；对不想动的列点**锁**保护。
5. **确认输出**：底栏看输出目录与格式；若提示「N 个输出已存在，会被覆盖」请先确认。
6. **点「开始清洗」**，页签自动切到「运行报告」。跑批中可点「中止」。
7. **取结果**：报告里展开任一文件可见产出路径，点「定位」在资源管理器里打开；「导出报告」把整份报告复制到剪贴板。

### 输入方式细节

| 方式 | 说明 |
|---|---|
| 选择文件 | 系统原生对话框，可多选 |
| 选择文件夹 | **递归**扫描全部子目录 |
| 拖拽 | WebView 拿不到本机绝对路径，文件字节会先落到系统临时目录，再走同一套清洗内核（不伪造路径），界面会显示落点 |
| 粘贴路径 | 同时支持文件与文件夹路径（多个用 `\|` 分隔）。是文件还是目录由服务端**按文件系统判定，不看后缀** —— `.dat`、无后缀的表格照收（内核本来就能猜读它们）。找不到的路径会明确提示，不会静默消失 |

队列里每一行显示：输出文件名（灰色小字）、行数、列数，以及标签：

- `将覆盖` —— 输出已存在；
- `读不了` —— 该文件读入失败，运行时会跳过并记入报告；
- `改名` —— 与其他同名文件冲突，输出名已加目录前缀。

点行 = 选中核对；行尾 `×` = 移出列表（在文件夹来源下会记住排除，重扫不会再拽回来）。

## 后缀写错不用改

从券商软件/银行网银导出的文件经常"名不副实"：报表叫 `成交明细.xlsx`，打开其实是逗号分隔的文本；也有把真 xlsx 改名成 `.csv` 交给下游的。**本工具按文件头判断真实格式，不用你先把后缀改对。**

### 怎么判断

| 文件头 | 判定 | 读法 |
|---|---|---|
| `PK\x03\x04`（ZIP 容器） | Excel | 按 `.xlsx` / `.xlsm` 读 |
| `D0CF11E0A1B11AE1`（OLE2 复合文档） | Excel | 按 `.xls` 读 |
| 其他 | 文本 | 编码探测 + 分隔符打分读成表格 |

判据只有文件头，后缀只在空文件、读不出文件头这类判不出的情况下才兜底。
引擎的首选也跟着容器走（ZIP → openpyxl，OLE → xlrd），装了 `python-calamine` 会先试它；实际用哪个引擎，顶栏会写出来。

### 两个方向都认

| 你的文件 | 真实内容 | 结果 |
|---|---|---|
| `成交明细.xlsx` | 逗号分隔的 CSV | 照常读成表格，**输出写 `成交明细_cleaned.csv`** |
| `成交明细.xlsx` | Tab 分隔的文本 | 照常读，**输出写 `成交明细_cleaned.csv`** |
| `持仓.csv` | 真 xlsx | 按 Excel 读，**输出写 `持仓_cleaned.xlsx`** |
| `日志.xls` | 文本 | 照常读，输出写 `日志_cleaned.csv` |

「跟随输入」跟随的是**真实格式**而不是后缀 —— 否则你会拿回一个"扩展名与内容不符"的文件。队列里预告的输出名就是最终产出名，可以直接照着核对。

### 在哪里看到

- **顶栏**：读出文本的假 Excel 会显示 **编码 + 分隔符**（真 Excel 显示的是引擎名）；右侧还会标出「样本 N 行」之类的口径提示；
- **「运行报告」页的警告区**：干跑预览与正式运行都会列出这条 —— `扩展名 .xlsx 但内容不是 Excel 容器 (无 ZIP/OLE 文件头), 已按文本读取（分隔符 ','）`；「导出报告」也会把它带进文本；
- 若列对不上（例如文本里的分隔符不是逗号），核对该条警告里的分隔符。

### 不会做的事

- **不"猜"真坏掉的 Excel**：文件头是 ZIP/OLE 但内容损坏时会明确报错（队列标 `读不了`、报告记失败），不会退回文本读出一整表乱码还照样落盘。
- **不绕过类型名单**：`.doc` `.docx` `.pdf` `.zip` `.png` 这类仍直接拒读，改后缀也进不来 —— 它们不是表格。
- **不改你的原文件**：一个字都不写回源文件，输出只写到输出目录。

## 清洗规则逐项说明

### 数值化

| 项目 | 默认 | 说明 |
|---|---|---|
| 智能数值化 | 开 | 千分位 `1,234.5`、全角数字 `１２３`、货币符号 `¥1,234`/`1,234元`、会计负数 `(1,234)`、科学计数法。解析成功变成真数值，**失败保留原值** |
| 中文单位换算 | 开 | `1.5亿` → `150000000`、`3千万` → `30000000`；全程整数运算，`1.005万` 精确等于 `10050`。关掉后保留原样 |

- 前导零列（`000001`、`00700`、Excel 导出的 `000001.0`）自动识别为**标识符列**，整列保留文本 —— 不会被洗成 `1`。
- **百分比不转换**：`12.5%` 保留原值（转 `12.5` 还是 `0.125` 语义有歧义）。
- **欧式小数/畸形分组不猜**：`1.234,5`、`1,23` 保留原值并给警告（猜错会差一千倍）。

### 日期

| 项目 | 默认 | 说明 |
|---|---|---|
| 统一为 YYYY-MM-DD | 开 | 按**内容**识别，不依赖列名；`2023年1月1日`、`2023.01.01`、`2023-01-01` 都统一。非法日期保留原值 |

带时间分量的列（Excel 日期时间、或 `2023-01-05 14:30:00`）会**拆成两列**：原列只留日期，新增 `<列名>_时间` 列保存 `14:30:00`。
不想多一列，就在源端先拆好，或关掉本项。

### 全角转半角

| 项目 | 默认 | 说明 |
|---|---|---|
| 全角字符转半角 | **关** | 开启后逐格作用于文本单元格（在去字符、数值化**之前**执行） |

- 关掉时：全角日期（`２０２３．１．８`）按解析失败**保留原值**；文本列一律不动；全角数字仍由数值化的内建窄表接住。
- 开启时：会连带改写名称、备注里的全角字母与标点（`ＨＫＣ／（）` → `HKC/()`）。**不想动的列请在「列检视」里点锁保护**。
- 全角代码转完仍是前导零，仍受标识符保护。

### 去字符

| 项目 | 默认 | 说明 |
|---|---|---|
| 要删除的字符 | 空 | 多个用逗号分隔（中英文逗号均可），例如 `*， #， 待定` |
| 仅针对指定列 | 关 | 开启后只处理「目标列名」这一列 |

- 目标列名留空 → 本次**不去字符**并记入警告；列名找不到 → 按全表处理并记入警告。
- 与单位换算冲突时：`万/亿/千/元` 这类单位字符属于单位换算职责，**不会被当去字符删掉**，界面会提示。

### 行裁剪

| 项目 | 默认 | 说明 |
|---|---|---|
| 删头部行数 | 0 | 删除表头之后的前 N 行（针对导出文件顶部的说明行/空行） |
| 删尾部行数 | 0 | 删除末尾 N 行（合计行、脚注等） |

多文件批量时，每个文件按**同一行数**裁剪。裁剪后文件为空会报错跳过该文件。

### 删除空行空列

| 项目 | 默认 | 说明 |
|---|---|---|
| 删除全空行 | 开 | 整行全为空（None / NaN / 空串 / 纯空白）才删 |
| 删除全空列 | 关 | 被删掉的列若正好是被保护的列，会记入警告 |

### 逐列保护

- 内核自动识别的标识符列会在规则面板里列出（只读提示）。
- 手动保护在「列检视」里操作，见下一节。

## 三个页签怎么读

### 列检视

逐列一行，展开看该列的「原值 → 结果」样本（每列最多 12 组）：

- **类型标签**：`文本` / `数值` / `日期` / `标识符` / `已保护` / `新增列`；
- `改动 N 格 / 共 M`：按当前规则会被改写的格数；
- `写法碰撞` 警告：同一列里两种写法会洗成同一个数值（如 `2023.1` 与 `2023.10`），洗完后分不出谁是谁；
- **锁按钮**：`已保护` = 该列整列回退为原值，不参与任何清洗通道。再点一次取消。

顶部显示「样本 N 行」时，所有统计都只基于**样本口径**（见「行为约定」）。

### 数据差异

只读差异矩阵，固定为**前 60 行 × 前 24 列**：被改写的格子高亮并**划线显示原值**，可直接肉眼校对。
不排序、不编辑、不分页；`Shift + 滚轮` 横向滚动。

### 运行报告

- **未运行时**：显示当前选中文件的干跑预估（样本口径）。
- **运行中**：进度百分比、当前阶段、逐文件结果。
- **每个文件**可展开：各项改动计数（数值化 / 单位换算 / 日期统一 / 全角转半角 / 去字符 / 保护回退 / 裁剪删空行）、标识符列、警告、产出路径 + 「定位」按钮。
- 「导出报告」把整份报告复制为文本到剪贴板；「再跑一次」重跑当前队列。
- 若出现「进度流断过一次」提示：SSE 重放窗口内没拿到的事件不会假装补齐，完整产出请以输出目录与登记清单为准。

底部进度条会显示阶段文案：`读取中 → 预处理 → 全角转半角 → 去字符 → 数值化 → 日期统一 → 列保护回退 → 写盘中 → 收尾`。

## 输出说明

- **默认输出目录**：输入文件公共父目录下的 `cleaned\` 子目录。可在底栏点「更改」自选（原生文件夹对话框）。
- **命名**：`原文件名_cleaned.csv` / `原文件名_cleaned.xlsx`。扩展名按**真实格式**给（见上文「后缀写错不用改」），与你在队列里看到的预告名一致。
  多个子目录存在同名文件时，输出名自动加目录前缀防覆盖；被跳过或改名的产出都会显式提示。
- **输出格式**（底栏右侧）：

  | 选项 | 行为 |
  |---|---|
  | 跟随输入（默认） | Excel 源（真 `.xlsx`/`.xls`/`.xlsm`）→ `.xlsx`；文本源（真 `.csv`/`.tsv`/`.txt`）→ `.csv`（`utf-8-sig`） |
  | xlsx | 一律写 `.xlsx` |
  | csv | 一律写 `.csv`（`utf-8-sig`） |
  | 两种都写 | 同一份数据各写一份 |

  「跟随输入」跟随的是**真实格式**（按文件头判定），不是文件名后缀：`成交.xlsx` 里其实是 CSV → 输出 `成交_cleaned.csv`。
  扩展名永远与真实内容一致。**写 csv 显著快于写 xlsx**（20 万行实测 0.6s vs 16.7s），追求速度就选 csv。
- **覆盖**：输出文件已存在会**直接覆盖**，底栏提前提示「N 个输出已存在，会被覆盖」。
- **产出登记**：输出目录写 `_stockcleaner_manifest.json` 记录真实产出。
  之后扫描文件夹时按「输出子树 + 登记清单」精确排除，**不会把自己的输出再洗一遍**。
  想重洗自己的输出，请逐个点选文件加入。
- **xlsx 特例**：`|整数| ≥ 2^53` 的格子按文本写出（避免 float64 舍入）；超过该量级的小数按解析失败保留原值。

## 行为约定（理解结果的关键）

1. **预览是样本口径**：默认只扫描**前 500 行**，界面显式标注「样本 500 行」且顶部有常驻提示；正式运行处理**全部行**。列类型识别同样只基于样本 —— 前 500 行没有前导零、后面才出现的代码列，预览会标成数值列而正式运行整列保留。这是有意的保守设计，不是 bug。
2. **解析失败一律保留原值**：不确定的写法（百分比、欧式小数、畸形千分位、非法日期、超精度小数）宁可原样保留，也绝不猜；这些都会在报告警告区列出。
3. **标识符列保护**：列中出现前导零数字串即整列保留文本。看到 `000001` 没变成 `1` 是**正确行为**。
4. **界面报的数 = 内核真的数**：预览与正式运行走同一条代码路径，「改动 N 格」与最终净改动一致；保护列不进入任何通道。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `000001` 洗完还是 `000001` | 标识符保护，整列保留文本。需要数值请先在源端去掉前导零语义 |
| `12.5%` 没变成数字 | 百分比语义有歧义，按失败保留原值 |
| `1.234,5` 没变成 `1234.5` | 欧式小数有歧义，保留原值并警告 |
| 全角日期 `２０２３．１．８` 没统一 | 开启「全角字符转半角」后重算 |
| 中文名称/备注被改了字符 | 关闭「全角转半角」，或在「列检视」里给该列点锁保护 |
| 目录扫描少了一批文件 | 在输出目录内或已登记的产出会被排除，界面会提示跳过数量与原因 |
| 报告里说"数值列"，正式运行整列没动 | 样本口径（前 500 行无前导零），全量以后半段为准 |
| 多出一列 `XXX_时间` | 日期列含时间分量，拆列保留；不需要就关掉「统一为 YYYY-MM-DD」 |
| 输出被顶掉了 | 同名输出直接覆盖，底栏提前提示；改输出目录或改文件名可避免 |
| 拖进来的文件去哪了 | 先落到系统临时目录（WebView 拿不到绝对路径），界面会显示落点 |
| 队列里某文件标「读不了」 | 该文件读入失败（二进制/损坏/编码异常），运行时会跳过并记入报告 |
| 粘贴路径后队列里什么都没有 | 路径不存在时会提示「找不到的路径」；若文件确实存在，检查路径里有没有多余的引号/换行，或粘成了相对路径 |
| `.xlsx` 的报表其实是 CSV | 自动按文本读（顶栏显示编码+分隔符）；「跟随输入」会把它写成 `.csv`（跟随真实格式，不是后缀） |
| 读出来只有一列（表头也是整行原文） | 文件用的分隔符不在 Tab / 半角逗号 / 分号 / 竖线之内（如全角逗号 `，`、空格）；在源端换成半角逗号或 Tab 再来洗 |
| 真损坏的 Excel 报「读不了」 | 文件头是 ZIP/OLE 但内容坏了：这是真损坏，不退回文本猜（否则会洗出一整表乱码）；回源端重新导出 |
| 启动闪一下黑屏 | 已按主题色对齐首帧背景；若仍出现，用 `SC_THEME=dark\|light` 钉死主题 |
| 想重洗自己上一次的输出 | 逐个点选文件加入（文件夹扫描会排除已登记产出） |

## 性能（实测，不是估算）

20 万行 × 12 列的 xlsx，同一台机器、走真实 HTTP 链路的端到端（`bench_e2e.py`）：

| 配置 | 端到端 |
|---|---|
| calamine 读 + 写 csv（全角开） | 15.0 s |
| calamine 读 + 写 csv（全角关，产品默认） | **14.0 s** |
| calamine 读 + 写 xlsx（全角开） | 40.3 s |
| calamine 读 + 写 xlsx（全角关，产品默认） | **37.9 s** |
| openpyxl 读 + 写 xlsx（历史对照） | 43.0 s |

分段计时（`bench_xlsx.py`，全表 20 万行 × 12 列）：

| 阶段 | 全角关 | 全角开 |
|---|---|---|
| 读 20 万行 (calamine) | 2.2 s | 2.2 s |
| 清洗（逐格解析，全表） | 7.7 s | 9.1 s |
| 写 xlsx | 16.7 s | 16.7 s |
| 写 csv | 0.6 s | 0.6 s |

三条结论：

1. **最贵的不是读，是写 xlsx。** 想快就在底栏把输出格式选成 csv（或"两种都写"），这一项省 16s。
2. calamine 省 7-8s，但**必须配 `dtype=object`**，否则股票代码 `000001` 会被读成 `1`；内核里有回归测试钉住这一点。
3. 清洗段是逐格 Python 循环，是内核热路径，也是唯一会随"保守优先"的规则变贵的地方（分组校验 + 精确缩放 + 碰撞留痕合计约 +3%）。真要提速的下一步是"先按列正则预筛再解析"（`bench_clean_stages.py` 拆出了四段成本）。

预览不受大文件影响：默认只算前 500 行样本，界面上显式标注"样本 N 行"。

## 设计原则

1. **逐值解析, 失败保留原值** — 永不静默改写或丢弃数据。
2. **标识符列保护** — 列中出现前导零数字串（`000001`/`00700`，含 Excel 导出的 `000001.0`）即整列保留文本。
3. **日期按内容识别** — 不依赖列名；非法日期保留原值；带时间分量的拆列并警告，截掉时分秒不可还原。
4. **读取阶段零破坏** — `dtype=object` + `keep_default_na=False`，类型转换全部交给显式清洗管道。
5. **编码/分隔符靠探测** — 严格解码顺序；分隔符按"每行能否切成同样多列"打分，引号里的字符不算票。
6. **去字符与单位换算互斥感知** — 勾选单位换算时"万/亿"不会被去字符先删掉，冲突记入警告。
7. **全程留痕** — 每个文件输出清洗报告；读取阶段的警告也带进预览。
8. **绝不让 pandas 静默破坏结构** — 字段数不一致的行显式修复，不静默当索引、不静默丢列。
9. **精确整数** — 纯整数以 int 全程精确运算（超过 2^53 也不丢），输出不会出现 `600519.0` 漂移。
10. **界面不得成为第二个解析器** — `webapp/backend` 只编排；数值一律转字符串送前端，否则 JS Number (float64) 会把内核保住的任意精度整数丢掉。
11. **排除文件要靠登记，不要靠猜名字** — manifest 精确登记 + 输出子目录隔离；登记不可用时宁可多跑一次。
12. **换引擎的前提是保真，不是快** — 任何"看起来只是换个库"的提速，都要先证明它不违反第 2、4 条。
13. **读取阶段连"缺失值名单"都不许动** — `N/A`/`NULL`/`nan`/`#N/A` 是文本，不是缺失。
14. **逗号是歧义，不是千分位** — 无条件 `replace(',','')` 会把欧式小数洗出错一千倍的数；分组必须合规，不合规保留原值。同列两种精度写法（`2023.1` 与 `2023.10`）洗成同一数值时也要留警告。
15. **宁可不解释，也不丢整列** — 结构存疑时补列名保住数据，猜错的代价是多一列，不是少一列。
16. **界面报的数必须是内核真的数** — 差异比较按索引对齐、用不截断的完整文本，预览与正式运行走同一条代码路径。
17. **后缀是标签，文件头是事实** — 读法与输出格式都按文件头判定；后缀只用来在对不出格式时兜底。但不做"引擎读失败再退回文本"的二次猜测：改名的 `.docx` 也是 ZIP，退回文本会洗出一整表乱码还照样落盘。

## 已知局限（有意为之）

- **百分比** `12.5%` 不转换：转成 `12.5` 还是 `0.125` 语义有歧义，保留原值最安全。
- **Excel 仅读第一个 sheet**。
- **带 BOM 的 UTF-16** 可以读（BOM 之后的字节必须是合法 UTF-16，否则按二进制拒读）；**无 BOM 的 UTF-16** 会被 NUL 守卫当二进制拦下（没有 BOM 就无法与二进制区分）；**Big5 源文件没有独立通道**（gb18030 字节域几乎覆盖 big5，会被"成功"解成乱码）—— 凡兜底解码一律写进警告，确认是 Big5 请先在源端转码。
- **全角开关默认关**（服务层与内核缺省一致，不传就不做）：开启后会改写名称/备注类文本列的全角字符，转换格数计入报告、界面常驻提示、任意列可点锁豁免。关掉时全角日期（２０２３．１．８）不被识别；全角数字（２３４）仍由数值化的内建窄表接住。
- **预览是样本口径**（前 500 行）：列类型识别同样只基于样本，前 500 行没有前导零、后面才有的列，预览标数值列而正式运行整列保留；界面常驻警告。
- **xlsx 里 `|int| ≥ 2^53` 的整数按文本写出**；**超过 2^53 的小数按"解析失败"保留原值**（float64 在这个量级连整数部分都放不下）。
- **SSE 重放窗口是 1024 条事件**（缓冲 2 万条）：一次批次约 340 个文件之内重连无损，超出会有显式的缺口标记，不假装补齐。
- **时间拆列会多出一列**；不想多一列就在源端先拆好，或关掉日期统一。
- **分组不合规的写法保留原文本**，该列可能出现数值与文本混排 —— 猜错的代价（差一千倍）比不猜大。
- **分隔符只在 Tab / 半角逗号 / 分号 / 竖线里选**：用全角逗号 `，`、空格等分隔的文件会被读成一列（表头是整行原文）。这类文件请在源端换成半角逗号或 Tab。
- **Excel 里以"数值 + 零填充格式"存的代码救不回来**（单元格里躺的就是数字 1），请先在 Excel 里改成文本列。
- **无表头的文件第一行会被当成列名**（本工具按"表头 + 数据"读，没有"无表头"选项）。
- **本地 API 只服务回环、对同用户进程不设防**：守卫只挡浏览器（Host 回环 + Origin 同源，同时挡 DNS rebinding），不挡本机其他程序。对单用户桌面工具是可接受的残余风险，别把它当成安全边界。
- 拖拽上传同名不覆盖（自动加序号）；输出端同名同样防覆盖改名、被跳过的产出显式提示。
- **改名过的文件按真实格式处理**：`.xlsx` 里其实是 CSV → 照常读成表格（留警告），输出写 `.csv`；反之 `.csv` 里其实是 xlsx → 按 Excel 读，输出写 `.xlsx`。真损坏的 Excel（文件头是 ZIP/OLE 但读不出来）会明确报错，不会退回文本洗出一整表乱码。

完整清单见各模块注释与 `verify_fullsample.py` 的逐项断言。

## 打包发布（Windows）

```bash
cd webapp
npm --prefix frontend run build                    # 先出前端 dist
.venv/Scripts/pyinstaller.exe StockCleaner.spec --noconfirm
.venv/Scripts/python.exe pack/smoke_test.py --exe dist/StockCleaner/StockCleaner.exe `
    --sample samples/A股样例_202301.csv --out "$env:TEMP/sc_smoke_out"
```

- 产物是 onedir 目录 `webapp/dist/StockCleaner/`，整体分发、双击 `StockCleaner.exe` 启动。选 onedir 不选 onefile：免去每次启动解压的等待，杀软误报也更少。
- 版本号两处同步改：`pack/version_info.txt`（exe 属性）与 `backend/app.py` 的 `APP_VERSION`。
- `pack/smoke_test.py` 是发布门槛：起 exe → `/api/meta` → 预览 → 真实清洗并校验产出，任何一步失败非零退出。
- 未签名的 PyInstaller exe 首次启动可能被 Windows SmartScreen 拦一下（"仍要运行"即可）。
