# StockCleaner

**金融/股票数据清洗工具 —— 把"看起来是数值"的单元格变成真正的数值，把"看起来是日期"的单元格变成统一的日期，全程不静默丢失任何信息。**

## 这是什么

从券商软件、Excel 导出的金融数据有一个共同的毛病：**整张表看起来是表格，实际上大半是文本**。
股票代码 `000001` 被吃成 `1`，金额 `1,234.5` 排不了序，日期 `2023年1月1日` 和 `2023-01-01`
混在一列，全角数字 `２３４` 混在半角里 —— 常规解法是"导入时让 pandas 自己猜"，
而猜错的代价是数据被静默改写或丢弃，你毫不知情。

StockCleaner 把这条路反过来走：**逐值解析，失败保留原值，每一步改动都留痕**。
它不是"再写一个 read_excel"，而是一套把"永不静默丢数据"当作硬约束的清洗内核，
外加一个"先看见、再动手"的桌面界面：

- **先预览后清洗**：规则一改立即看到每一列 `原值 → 结果` 的逐格对照，全程只读不落盘；
- **不确定就保留**：欧式小数、百分比、畸形千分位这类有歧义的写法，宁可保留原文本也不猜；
- **界面报的数必须是内核真的数**：预览与正式运行走同一条代码路径，报告数字可对账。

清洗内核 `cleaner_core.py` 是唯一实现，无 GUI 依赖、可独立测试；界面只是编排层。

## 洗之前 → 洗之后

| 原始值 | 清洗后 | 说明 |
|---|---|---|
| `000001` / `00700` / `000001.0` | 原样保留（文本） | 识别为标识符列，前导零不能丢 |
| `1,234.5` | `1234.5` | 千分位 |
| `¥1,234` / `1,234元` | `1234` | 货币符号、单位后缀 |
| `(1,234)` | `-1234` | 会计负数 |
| `１２３` | `123` | 全角数字在数值化内建翻译；文本列的全角转半角通道默认关，可开启，可按列豁免 |
| `1.5亿` / `3千万` / `1.5万亿` | `150000000` / `30000000` / `1500000000000` | 中文单位换算，全程整数运算 |
| `1.005万` | `10050` | 精确整数缩放，不是 `10049.999999999998` |
| `2023年1月1日` / `2023.01.01` | `2023-01-01` | 日期按内容识别，不依赖列名（`２０２３．１．８` 需开启全角转半角） |
| `2023-01-05 14:30:00` | `2023-01-05` + 新列 `列名_时间`（`14:30:00`） | 时间分量拆列保留，不截成日期 |
| `600519.0` | `600519` | 纯整数全程精确，无 `x.0` 表示漂移 |
| `N/A` / `NULL` | 原样保留 | 不吃 pandas 缺失值名单里的文本 |
| `1.234,5`（欧式小数）/ `1,23`（畸形分组）/ `12.5%` | **保留原值 + 警告** | 有歧义的写法不猜 |

## 核心特性

**读得进来**
- 支持 `.csv` `.tsv` `.txt` `.xlsx` `.xls` `.xlsm`；后缀不对但内容是文本表格的（`.dat` `.log`、无后缀）按文本猜读并留警告，含 NUL 的真二进制拒读。
- 编码探测：BOM（utf-8 / UTF-16）+ 严格解码顺序 utf-8 → gb18030 → big5，兜底解码一律写进警告。
- 分隔符按"能不能把每行切成同样多列"打分（Tab/逗号/分号/竖线），引号里的字符不算票。
- 读取阶段零破坏：`dtype=object` 文本保真 + `keep_default_na=False`，字段数与表头不一致的行显式修复，绝不让 pandas 静默当索引、丢列、吃文本。
- Excel 读取可选 Rust 引擎 [python-calamine](https://github.com/dimastbk/python-calamine)（快 4-5 倍，需配 `dtype=object` 保住前导零），没装自动退回 openpyxl。

**洗得干净**
- 智能数值化、中文单位换算（整数运算）、四种日期写法统一、全角转半角、指定列/全表去字符、行裁剪、删除全空行/列。
- 逐列保护：任意一列可标记"不参与清洗"，保护列不进任何通道，"报告说改了 N 格"与净改动始终一致。
- 带时间分量的列拆成日期 + `列名_时间`，不把 `14:30` 与 `09:15` 截成同一个日期。
- 超过 float64 精度界的整数全程精确；xlsx 里 `|int| ≥ 2^53` 的格子按文本写出，不做舍入。

**看得见（界面不是换个皮肤）**
- **列检视**：每列给出逐格 `原值 → 结果` 对照、改动格数、识别类型（标识符/数值/日期/文本/新增列），按索引配对、行号是原文件位置，删过一行也不串位。
- **数据差异**：只读差异矩阵，被改写的格子划线显示原值，坏行并回了哪个字段、全角日期为什么没动，直接看得见。
- **运行报告**：逐文件的各类改动计数、标识符列、时间拆列、写法碰撞、警告、输出路径，可复制成文本。
- **输入三通道**：原生对话框 / 拖拽 / 粘贴路径；进度走 SSE（带 seq、服务端缓冲、断线重连回放最近 1024 条并有缺口标记）。
- **输出格式可选**：跟随输入 / xlsx / csv / 两种都写；扩展名永远与真实内容一致。

**不重复吃进自己的输出**
- 默认输出到输入目录下的 `cleaned/` 子目录，并在输出目录写 `_stockcleaner_manifest.json` 登记真实产出；扫描时按"输出子树 + 登记清单"精确排除，不靠猜文件名。登记不可用时宁可多跑一次，也不静默漏文件。

## 快速开始

要求 Python ≥ 3.11。

```bash
cd webapp
uv venv && uv pip install -r requirements.txt      # 或 pip install -r requirements.txt
cd frontend && npm install && npm run build        # 产出 dist/
cd .. && python run.py                             # 起桌面窗口
```

不想看到终端窗口就用 `pythonw run.py`（同一个入口，只是没有控制台）。`samples/` 里有现成的演示数据（含 601 行"一份数据踩遍全部清洗路径"的全功能验证样例），进来就能试。

其他模式：

```bash
python run.py --no-shell              # 不起窗口, 用系统浏览器
python run.py --dev                   # 加载 vite dev server (需先在 frontend/ npm run dev)
python run.py --port 8720 --no-shell  # 固定端口, 便于自测与代理
```

环境变量：

| 变量 | 作用 |
|---|---|
| `SC_THEME=dark\|light` | 钉死默认主题（不跟随系统），打包成 exe 或做外观预设时用 |
| `SC_EXCEL_ENGINE=openpyxl\|xlrd\|calamine` | 钉死 Excel 读取引擎，既是兜底也是 A/B 计时对照组 |
| `SC_DEBUG=1` | `run.py` 带 devtools 启动 |

依赖说明：`python-calamine` 是非必需项，装了就优先用、没装自动退回 openpyxl，功能不受影响。
`xlsxwriter` 实测过但**没有**采用：写 20 万行它 17.4s、openpyxl 16.7s，"换 xlsxwriter 提速"在这个量级上不成立。

## 性能（实测，不是估算）

20 万行 × 12 列的 xlsx，同一台机器、走真实 HTTP 链路的端到端（`bench_e2e.py`）：

| 配置 | 端到端 |
|---|---|
| calamine 读 + 写 csv（全角开） | 15.0 s |
| calamine 读 + 写 csv（全角关，产品默认） | **14.0 s** |
| calamine 读 + 写 xlsx（全角开） | 40.3 s |
| calamine 读 + 写 xlsx（全角关，产品默认） | **37.9 s** |
| openpyxl 读 + 写 xlsx（历史对照） | 43.0 s |

分段计时（`bench_xlsx.py`，全表 20 万行 × 12 列）：

| 阶段 | 全角关 | 全角开 |
|---|---|---|
| 读 20 万行 (calamine) | 2.2 s | 2.2 s |
| 清洗（逐格解析，全表） | 7.7 s | 9.1 s |
| 写 xlsx | 16.7 s | 16.7 s |
| 写 csv | 0.6 s | 0.6 s |

三条结论：

1. **最贵的不是读，是写 xlsx。** 想快就在底栏把输出格式选成 csv（或"两种都写"），这一项省 16s。
2. calamine 省 7-8s，但**必须配 `dtype=object`**，否则股票代码 `000001` 会被读成 `1`；内核里有回归测试钉住这一点。
3. 清洗段是逐格 Python 循环，是内核热路径，也是唯一会随"保守优先"的规则变贵的地方（分组校验 + 精确缩放 + 碰撞留痕合计约 +3%）。真要提速的下一步是"先按列正则预筛再解析"（`bench_clean_stages.py` 拆出了四段成本）。

预览不受大文件影响：默认只算前 500 行样本，界面上显式标注"样本 N 行"。

## 设计原则

1. **逐值解析, 失败保留原值** — 永不静默改写或丢弃数据。
2. **标识符列保护** — 列中出现前导零数字串（`000001`/`00700`，含 Excel 导出的 `000001.0`）即整列保留文本。
3. **日期按内容识别** — 不依赖列名；非法日期保留原值；带时间分量的拆列并警告，截掉时分秒不可还原。
4. **读取阶段零破坏** — `dtype=object` + `keep_default_na=False`，类型转换全部交给显式清洗管道。
5. **编码/分隔符靠探测** — 严格解码顺序；分隔符按"每行能否切成同样多列"打分，引号里的字符不算票。
6. **去字符与单位换算互斥感知** — 勾选单位换算时"万/亿"不会被去字符先删掉，冲突记入警告。
7. **全程留痕** — 每个文件输出清洗报告；读取阶段的警告也带进预览。
8. **绝不让 pandas 静默破坏结构** — 字段数不一致的行显式修复，不静默当索引、不静默丢列。
9. **精确整数** — 纯整数以 int 全程精确运算（超过 2^53 也不丢），输出不会出现 `600519.0` 漂移。
10. **界面不得成为第二个解析器** — `webapp/backend` 只编排；数值一律转字符串送前端，否则 JS Number (float64) 会把内核保住的任意精度整数丢掉。
11. **排除文件要靠登记，不要靠猜名字** — manifest 精确登记 + 输出子目录隔离；登记不可用时宁可多跑一次。
12. **换引擎的前提是保真，不是快** — 任何"看起来只是换个库"的提速，都要先证明它不违反第 2、4 条。
13. **读取阶段连"缺失值名单"都不许动** — `N/A`/`NULL`/`nan`/`#N/A` 是文本，不是缺失。
14. **逗号是歧义，不是千分位** — 无条件 `replace(',','')` 会把欧式小数洗出错一千倍的数；分组必须合规，不合规保留原值。同列两种精度写法（`2023.1` 与 `2023.10`）洗成同一数值时也要留警告。
15. **宁可不解释，也不丢整列** — 结构存疑时补列名保住数据，猜错的代价是多一列，不是少一列。
16. **界面报的数必须是内核真的数** — 差异比较按索引对齐、用不截断的完整文本，预览与正式运行走同一条代码路径。

## 已知局限（有意为之）

- **百分比** `12.5%` 不转换：转成 `12.5` 还是 `0.125` 语义有歧义，保留原值最安全。
- **Excel 仅读第一个 sheet**。
- **带 BOM 的 UTF-16** 可以读（BOM 之后的字节必须是合法 UTF-16，否则按二进制拒读）；**无 BOM 的 UTF-16** 会被 NUL 守卫当二进制拦下（没有 BOM 就无法与二进制区分）；**Big5 源文件没有独立通道**（gb18030 字节域几乎覆盖 big5，会被"成功"解成乱码）—— 凡兜底解码一律写进警告，确认是 Big5 请先在源端转码。
- **全角开关默认关**（服务层与内核缺省一致，不传就不做）：开启后会改写名称/备注类文本列的全角字符，转换格数计入报告、界面常驻提示、任意列可点锁豁免。关掉时全角日期（２０２３．１．８）不被识别；全角数字（２３４）仍由数值化的内建窄表接住。
- **预览是样本口径**（前 500 行）：列类型识别同样只基于样本，前 500 行没有前导零、后面才有的列，预览标数值列而正式运行整列保留；界面常驻警告。
- **xlsx 里 `|int| ≥ 2^53` 的整数按文本写出**；**超过 2^53 的小数按"解析失败"保留原值**（float64 在这个量级连整数部分都放不下）。
- **SSE 重放窗口是 1024 条事件**（缓冲 2 万条）：一次批次约 340 个文件之内重连无损，超出会有显式的缺口标记，不假装补齐。
- **时间拆列会多出一列**；不想多一列就在源端先拆好，或关掉日期统一。
- **分组不合规的写法保留原文本**，该列可能出现数值与文本混排 —— 猜错的代价（差一千倍）比不猜大。
- **Excel 里以"数值 + 零填充格式"存的代码救不回来**（单元格里躺的就是数字 1），请先在 Excel 里改成文本列。
- **无表头的文件第一行会被当成列名**（本工具按"表头 + 数据"读，没有"无表头"选项）。
- **本地 API 只服务回环、对同用户进程不设防**：守卫只挡浏览器（Host 回环 + Origin 同源，同时挡 DNS rebinding），不挡本机其他程序。对单用户桌面工具是可接受的残余风险，别把它当成安全边界。
- 拖拽上传同名不覆盖（自动加序号）；输出端同名同样防覆盖改名、被跳过的产出显式提示。

完整清单见各模块注释与 `verify_fullsample.py` 的逐项断言。

## 打包发布（Windows）

```bash
cd webapp
npm --prefix frontend run build                    # 先出前端 dist
.venv/Scripts/pyinstaller.exe StockCleaner.spec --noconfirm
.venv/Scripts/python.exe pack/smoke_test.py --exe dist/StockCleaner/StockCleaner.exe `
    --sample samples/A股样例_202301.csv --out "$env:TEMP/sc_smoke_out"
```

- 产物是 onedir 目录 `webapp/dist/StockCleaner/`，整体分发、双击 `StockCleaner.exe` 启动。选 onedir 不选 onefile：免去每次启动解压的等待，杀软误报也更少。
- 版本号两处同步改：`pack/version_info.txt`（exe 属性）与 `backend/app.py` 的 `APP_VERSION`。
- `pack/smoke_test.py` 是发布门槛：起 exe → `/api/meta` → 预览 → 真实清洗并校验产出，任何一步失败非零退出。
- 未签名的 PyInstaller exe 首次启动可能被 Windows SmartScreen 拦一下（"仍要运行"即可）。

## 项目结构

```
stockcleaner/
├── cleaner_core.py          清洗内核: 唯一实现, 无 GUI 依赖, 可独立测试
├── test_cleaner_core.py     内核回归测试 (33 项)
└── webapp/                  桌面界面
    ├── run.py               入口: 本地服务 + pywebview 桌面壳
    ├── backend/             FastAPI 层 (只做编排, 不含任何解析逻辑)
    │   ├── core.py          预览/干跑 + 列级 diff + 输出名计划
    │   ├── jobs.py          批量任务线程 + 可重放的 SSE 事件缓冲
    │   ├── manifest.py      产出登记: 精确排除自己的输出, 不靠猜文件名
    │   └── app.py           路由 / 静态托管 / 原生对话框桥接
    ├── frontend/            React 18 + Vite + Tailwind v4 + Radix
    ├── samples/             演示与自测数据
    ├── make_fullsample.py   生成"全功能验证"对抗样例 (601 行)
    ├── verify_fullsample.py 全功能样例逐项实测 (对着运行中的服务)
    ├── api_selftest.py      服务层契约自测 (60 项断言, 需要起服务)
    ├── test_service_layers.py 编排/任务/登记层的离线分层回归 (不起服务)
    ├── bench_*.py|ps1       性能剖析: 分段计时 / 端到端 / 引擎 A/B / 热路径四段
    └── StockCleaner.spec    PyInstaller 打包配置
```
