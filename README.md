# StockCleaner

金融/股票数据清洗工具: 在不丢失信息的前提下, 把"看起来是数值"的单元格变成
真正的数值, 把"看起来是日期"的单元格变成统一的日期文本。

界面为 v2.1 (Web 技术栈)，内核本轮为 v2.2。上一轮加了三样能力: 全角转半角通道、
calamine 读取引擎、输出格式可选。其中全角通道**产品层默认开、内核层默认不传就不做**
(两层的默认值故意不同, 理由见 `webapp/backend/core.py` 注释); 关掉该开关后行为与 v2.0 一致。

v2.2 不是加功能, 是把"永不静默丢数据"这条口号补到能守住的程度 —— 全部由对抗性审查
实测抓出来，改动清单见下面「设计原则」里的 13-16 条与「已知局限」:

- 单位换算不再经过 float 乘法 (`1.005万` 以前写成 `10049.999999999998`)；
- 千分位分组不合规时不猜 (`1.234,5` 以前被洗成 `1.2345`，差一千倍)；
- 读取阶段不再用 pandas 的缺失值名单 (`N/A / NULL / nan / #N/A` 以前直接变成空，
  而且原值也渲染成空，差异页根本看不出来)；
- 首列像行号时不再整列消失 (以前交给 `index_col=0`，写出时 `index=False`，一列没了且零警告)；
- Excel 里的时间分量不再被截成日期，改成拆出 `列名_时间` 一列并警告；
- 列检视的"改动格数"改为按索引对齐 (删过一行就会整体串位，实测一列从没动过的文本
  被报出 488 格改动，真值是 1)；
- 分隔符改按"能不能把每行切成同样多列"判定，不再数引号里的逗号；
- SSE 重连改回放**最近**一段并带缺口标记 (以前回放最旧的 1024 条，长任务重连必然拿不到
  `job_end`，进度条永远停在"处理中")；产出登记加锁 + 唯一 tmp 名 (并发批次实测丢掉一半登记)。

## 运行

```bash
cd webapp
uv venv && uv pip install -r requirements.txt      # 或 uv sync
cd frontend && npm install && npm run build        # 产出 dist/
cd .. && python run.py                             # 起桌面窗口
```

不想看到终端窗口就用 `pythonw run.py`（同一个入口，只是没有控制台）。代价是壳里那几行
`[StockCleaner] ...` 提示会落进 devnull，排障时请回到 `python run.py` 或加 `SC_DEBUG=1`。

依赖里有一个非必需项值得说明：`python-calamine` 是 Rust 实现的 Excel 读取引擎，
装了就优先用（快 4-5 倍），没装会自动退回 openpyxl，功能不受影响。
`xlsxwriter` 我实测过但**没有**采用：写 20 万行它 17.4s、openpyxl 16.7s，网上常说的
"换 xlsxwriter 提速"在这个量级上不成立。

环境变量：

| 变量 | 作用 |
|---|---|
| `SC_THEME=dark\|light` | 钉死默认主题（不跟随系统）。打包成 exe 或做外观预设时用 |
| `SC_EXCEL_ENGINE=openpyxl\|xlrd\|calamine` | 钉死 Excel 读取引擎。既是"新引擎读某类怪文件"时的兜底，也是 A/B 计时对照组 |
| `SC_DEBUG=1` | `run.py` 带 devtools 启动 |
| `UV_DEFAULT_INDEX` / npm registry | 按工作区规范走国内镜像 |

其他模式:

```bash
python run.py --no-shell              # 不起窗口, 用系统浏览器
python run.py --dev                   # 加载 vite dev server (需先在 frontend/ npm run dev)
python run.py --port 8720 --no-shell  # 固定端口, 便于自测与代理
```

自测:

```bash
python test_cleaner_core.py                       # 内核回归 (32 项)
python webapp/test_service_layers.py               # 编排/任务/登记层分层回归, 不起服务
python run.py --port 8720 --no-shell &            # 另开一个终端
python api_selftest.py http://127.0.0.1:8720      # 服务层契约 + 端到端
python make_fullsample.py                         # 生成全功能样例 (幂等)
python verify_fullsample.py http://127.0.0.1:8720 # 全功能样例逐项实测
```

`test_service_layers.py` 之所以单独存在: 它盯的是"界面报的数 == 内核真的数"这一类账
(列检视的改动格数要和按索引对齐独立算出来的真值逐列相等、SSE 重连必须能拿到
`job_end`、并发登记不能丢) —— 这些既不在内核里, 也不适合靠起服务来断言。

## 打包发布 (Windows)

```bash
cd webapp
npm --prefix frontend run build                    # 先出前端 dist
.venv/Scripts/pyinstaller.exe StockCleaner.spec --noconfirm
.venv/Scripts/python.exe pack/smoke_test.py --exe dist/StockCleaner/StockCleaner.exe `
    --sample samples/A股样例_202301.csv --out "$env:TEMP/sc_smoke_out"
```

- 产物是 onedir 目录 `webapp/dist/StockCleaner/` (整体分发, 双击 `StockCleaner.exe`
  启动, 无控制台)。选 onedir 不选 onefile: 免去每次启动解压 ~百 MB 的等待, 杀软误报也更少。
- `StockCleaner.spec` 注释里写了打包要点: cleaner_core 在上一级要用 pathex 登记、
  前端 dist 与窗口图标是运行期数据、uvicorn 动态导入的子模块要显式钉一份。
- 版本号两处同步改: `pack/version_info.txt` (exe 属性) 与 `backend/app.py` 的 APP_VERSION。
- `pack/smoke_test.py` 是发布门槛: 起 exe → /api/meta → 预览 → 真实清洗并校验产出,
  任何一步失败非零退出; 对未打包的调试实例可改用 `--base http://127.0.0.1:8720`。
- 未签名的 PyInstaller exe 首次启动可能被 Windows SmartScreen 拦一下 ("仍要运行"即可)。

## 界面为什么不是换个皮肤

前身是一个 PyQt5 表单版（已移除）。它的结构性问题是:
**配置完直接跑, 跑完才知道数据变成了什么**。现在这版把它倒过来, 先看见再动手:

- **列检视**: 每一列给出 `原值 → 结果` 的逐格对照、改动格数、识别类型
  (标识符 / 数值 / 日期 / 文本 / 新增列), 规则一改就重算, 全程只读不落盘。
  对照按**索引**配对、行号是原文件里的位置 —— 否则删过一行就会整体串位。
- **逐列保护**: 任何一列可标记为"不参与清洗"。实现方式是清洗后把该列回滚为
  原值, 因此不需要第二套清洗逻辑; 保护逻辑在内核 `clean_table` 内部执行,
  预览与正式运行走**同一条代码路径**, 不可能分叉。列名按字符串口径匹配,
  表头是年份 (标签是 int) 时点的锁同样生效; 保护列不进任何清洗通道
  (全角/去字符/数值化/日期), 所以"报告说改了 N 格"与"净改动"始终一致。
- **数据差异**: 只读差异矩阵, 被改写的格子划线显示原值; 坏行被并回哪个字段、
  全角日期为什么没动, 都直接看得见。
- **运行报告**: 逐文件的数值化/单位换算/日期统一/去字符/保护回退计数、标识符列、
  日期时间拆列、写法碰撞、警告、输出路径, 可复制成文本。进度走 SSE, 事件带 seq
  且服务端缓冲; 重连回放**最近** 1024 条, 有缺口时显式发一条 `replay_gap` 并在界面上
  标"只覆盖重放窗口内的部分", 不再假装补齐。
- **输入三通道**: 原生对话框 (系统资源管理器) / 拖拽 / 粘贴绝对路径回车。
  拖拽在 WebView 里拿不到本机路径, 所以走 `/api/upload` 落到临时目录再进同一套内核,
  不在前端伪造路径。
- **输出格式可选**: 底栏可选 `跟随输入 / xlsx / csv / 两种都写`。默认跟随输入
  （Excel 出 xlsx、文本出 csv），大文件想快就选 csv（见下面性能表）。
  扩展名永远与真实内容一致。
- **不重复吃进自己的输出**: 默认输出到输入目录下的 `cleaned/` 子目录（结构隔离），
  同时在输出目录写 `_stockcleaner_manifest.json` 登记真实产出路径；扫描时按
  "输出子树 + 登记清单"两条规则排除，**不再靠猜文件名**。显式点选的文件永远照洗。
  登记只认**当前输出目录**里那一份（不读输入树里其他目录的清单，避免一份伪造/残留的
  清单让扫描器静默跳过真实数据）；登记读不到时退化成"什么都不排除"，宁可多跑一次
  也不静默漏文件。
- **全角转半角（默认开，可关）**: 逐格把全角字符转半角，在去字符与数值化之前执行。
  开着时 `２０２３．１．８` 会被日期识别接住；关掉则按"解析失败"保留原值。
  范围含全角字母与标点，所以**会改写名称/备注这类文本列**，转换格数一律计入报告，
  界面上也常驻一条提示；不想动的列在列检视里点锁保护即可。
- 输出目录默认跟随输入位置；同名输出、防覆盖改名、被跳过的产出都会显式提示，
  不静默覆盖也不静默漏文件。

## 性能 (实测, 不是估算)

20 万行 x 12 列的 xlsx，同一台机器、走真实 HTTP 链路的端到端。
下表是 **v2.2 修复之后重测**的数（`bench_e2e.py` 的归因隔离段，同一文件同一服务，
只切开关）：

| 配置 | 端到端 |
|---|---|
| calamine 读 + 写 xlsx（全角关 = 与改造前同口径） | 37.9 s |
| calamine 读 + 写 xlsx（全角开，产品默认） | 40.3 s |
| calamine 读 + 写 csv（全角关） | 14.0 s |
| calamine 读 + 写 csv（全角开，产品默认） | **15.0 s** |
| openpyxl 读 + 写 xlsx（改造前的路径，历史数字） | 43.0 s |

对照 v2.1 记的 35.1 s / 10.9 s：两个输出格式各自都慢了约 2.8~3.1 s，
**同一份绝对增量落在两条行上，说明它出在读/洗这一段而不是写**，
也就是 v2.2 那批"保守优先"的代价（逐格分组校验、精确整数缩放、写法碰撞留痕）。
分段计时（`bench_xlsx.py`，全表 20 万行 x 12 列）：

| 阶段 | 全角关 | 全角开 |
|---|---|---|
| 读 20 万行 (calamine) | 2.2 s | 2.2 s |
| 清洗（逐格解析，全表） | 7.7 s | 9.1 s |
| 写 xlsx | 16.7 s | 16.7 s |
| 写 csv | 0.6 s | 0.6 s |

旧实现清洗段记的是 7.5 s，同口径（全角关）现在 7.7 s —— 涨幅约 3%；
碰撞检测本来要再扫一遍全列，已经折进同一遍循环，另外纯整数格直接跳过写法判定
（那类格子不可能发生精度碰撞）。

三条结论：

1. **最贵的不是读，是写 xlsx。** 想快就在底栏把输出格式选成 csv（或"两种都写"），
   这一项就省 16s。
2. 读引擎换 calamine 省 7-8s，但**必须配 `dtype=object`**：裸用会把股票代码
   `000001` 读成 `1`，正好踩第 2 条原则。内核里有回归测试钉住这一点。
3. 清洗那段是逐格 Python 循环，是内核热路径，也是唯一会随"保守优先"的规则变贵的地方
   （v2.2 的分组校验 + 精确缩放 + 碰撞留痕合计约 +3%）。真要提速的下一步仍然是
   "先按列正则预筛再解析"（`bench_clean_stages.py` 拆出了四段成本）。

预览不受大文件影响：默认只算前 500 行样本，界面上会显式标"样本 N 行"。

## 设计原则 (第一性原理)

1. **逐值解析, 失败保留原值** — 永不静默改写或丢弃数据。
2. **标识符列保护** — 列中出现前导零数字串 (`000001`/`00700`, 含 Excel 导出的
   "x.0" 形式 `000001.0`) 即整列保留文本, 股票代码不会被吃成数字。
3. **日期按内容识别** — 支持 `2023-01-01` / `2023/1/1` / `2023.01.01` / `2023年1月1日`,
   不依赖列名; 非法日期 (如 2023.2.30) 保留原值。带时间分量的 (Excel 日期时间、
   `2023-01-05 14:30:00`) 拆成日期列 + `列名_时间` 列并警告 —— 截掉时分秒不可还原。
4. **读取阶段零破坏** — CSV/TXT 按 `dtype=object` 文本保真读入, Excel 同理;
   并且一律 `keep_default_na=False`, 不让 pandas 的缺失值名单把 `N/A`/`NULL` 这类
   文本吃掉 (见第 13 条)。类型转换全部交给显式清洗管道。
5. **编码/分隔符靠探测** — BOM + 严格解码顺序 (utf-8 → gb18030 → big5),
   分隔符按"能不能把每行切成同样多列"打分 (Tab/逗号/分号/竖线), 引号里的字符不算票。
6. **去字符与单位换算互斥感知** — 勾选单位换算时, "万/亿" 等单位字符不会被
   去字符功能先删掉; 冲突时记入警告。
7. **全程留痕** — 每个文件输出清洗报告 (数值化/单位换算/日期统一的单元格数、
   标识符列、编码与分隔符、跳过的坏行)。新界面把读取阶段的警告也带进预览,
   不用等到跑完才发现数据已经被修过。
8. **绝不让 pandas 静默破坏结构** — 字段数与表头不一致的行由本工具显式修复
   (超出的字段并回最后一个值 / 不足的补空), 不会像 pandas 默认行为那样把
   首列静默当索引 (单列 CSV 的 `1,234` 会被拆成索引 1 + 值 234) 或静默丢列。
9. **精确整数** — 纯整数以 int 全程精确运算 (超过 float64 的 2^53 精度界也不丢),
   输出不会出现 `600519.0` 这类表示漂移。
10. **界面不得成为第二个解析器** — `webapp/backend` 只编排, 预览必须调用
    `clean_table` 本体再逐格 diff; 数值一律转成字符串送前端, 否则 JS Number
    (float64) 会在最后一步把内核保住的任意精度整数丢掉。
11. **排除文件要靠登记, 不要靠猜名字** — 早先用 `*_cleaned` 后缀猜"这是不是自己的输出",
    会静默跳过用户自己命名的 `report_cleaned.csv`, 于是"少洗了一个文件"而界面毫无提示。
    漏文件比多跑一次严重, 所以换成 manifest 精确登记 + 输出子目录结构隔离,
    且登记不可用时宁可多跑一次。清单只认**当前输出目录**那一份, 输入树里其他目录的
    登记不被信任 —— 否则一份伪造/残留的清单能让扫描器静默跳过真实数据。
    登记本身的读-改-写要加锁、临时文件名要唯一: 两个批次同时写同一个输出目录时,
    不加锁实测 60 条只剩 30 条, 被抹掉的那些下次扫描就不再排除。
12. **换引擎的前提是保真, 不是快** — calamine 快 4-5 倍, 但裸用会吃掉前导零;
    配上 `dtype=object` 才可用, 并且回归测试里钉死了这一条。任何"看起来只是换个库"的
    提速, 都要先证明它不违反第 2、4 条。
13. **读取阶段连"缺失值名单"都不许动** — `dtype=object` 只挡住类型推断, 挡不住
    pandas 默认把 `N/A` / `NULL` / `nan` / `#N/A` 这些**文本**换成 NaN。后果是三步连着的:
    值在第一步就没了、`json_safe` 把原值和结果都渲染成空、输出文件里那一格真的空了 ——
    全程零警告。所以所有 read_csv / read_excel 恒定 `keep_default_na=False`,
    空单元格由引擎给 None/空串, 不靠猜名单。
14. **逗号是歧义, 不是千分位** — 无条件 `replace(',','')` 会把欧式小数 `1.234,5`
    (即 1234.5) 洗成 1.2345, 差一千倍; `1,23`、`1,234,5` 这类畸形分组也会被照单全收。
    现在分组必须是"1-3 位 + 若干组 3 位", 不合规一律按解析失败保留原值。
    同理, 同一列里两种**精度写法**洗成同一个数值 (`2023.1` 与 `2023.10`) 时数值没错,
    但"这格原来写的是哪个"再也分不出来, 所以要写进警告而不是闭嘴 ——
    分组符、货币符、单位后缀、会计括号这些差异会先折平, 不会误报。
15. **宁可不解释, 也不丢整列** — "数据行比表头多一列且首列是数字"确实很像
    `to_csv(index=True)` 的产物, 但把它交给 `index_col=0` 再 `index=False` 写出,
    就是原则 8 禁止的那件"静默当索引"的事。现在给首列补一个 `(索引列)` 列名保住它,
    并提示用户在源端决定去留: 猜错的代价是多一列, 不是少一列。
    分隔符嗅探同理 —— 只按"能不能把每行切成同样多列"打分, 引号里的字符不算票。
16. **界面报的数必须是内核真的数** — 预览的改动格数以前把"清洗前的列"和"清洗后的列"
    按位置 zip, 只要管道删过一行就整体串位: 全功能样例实测代码列报 488 格改动、真值 1,
    而按标签取值的差异页显示没动, 两个页签互相打脸。现在一律按索引对齐、行号用原始位置,
    并且比较用不截断的 `cell_repr` (显示串截到 160 字符, 拿它比会漏掉尾部改动)。
    服务层的字段清单也只留 `public_report` 一份, 预览与正式运行不再各写一遍白名单。

## 功能

- 支持 `.csv` `.tsv` `.txt` `.xlsx` `.xls` `.xlsm` (输出: `.xlsx` / `utf-8-sig` 的 `.csv`)；
  后缀不对但内容确实是文本表格的 (`.dat` `.log` 或没有后缀) 也按文本猜读并留警告,
  含 NUL 字节的真二进制则直接拒读。
  后缀放开后要排除的东西也变多了，所以文件夹扫描会跳过：自己的登记文件、`*.tmp`、
  任何一层以 `.` 开头的路径 (`.venv` `.git`)、Office 的 `~$` 锁文件。
  点名选进来的文件不受这些排除影响 (那是明确意图)
- 智能数值化: 千分位 `1,234.5`、全角 `２３４`、货币 `¥1,234`、`1,234元`、
  会计负数 `(1,234)`、科学计数法 `1.5e9`；分组不合规 (`1,23` / `1.234,5`) 保留原值
- 中文单位换算: `1.5亿` → `150000000`, `3千万` → `30000000`, `1.5万亿` → `1.5e12`，
  全程整数运算 (`1.005万` 就是 `10050`，不会写成 `10049.999999999998`)
- 日期统一: 四种写法按内容识别; 带时间分量的列拆成 `日期` + `列名_时间` 两列，
  不把 `14:30` 与 `09:15` 截成同一个日期
- 行裁剪 (头/尾)、删除全空行/列、指定列或全表去字符、批量递归处理
- 批量模式下不同子目录同名文件自动生成互不覆盖的输出名

## 已知局限 (有意为之)

- **百分比** `12.5%` 不转换: 转成 `12.5` 还是 `0.125` 语义有歧义, 保留原值最安全。
- **Excel 仅读第一个 sheet**。
- **无 BOM 的 UTF-16** 文件无法可靠识别, 可能被 gb18030 兜底成乱码 (极少见)。
- **Big5 (繁体) 文件没有独立通道**: gb18030 的字节域几乎覆盖 big5, Big5 源文件
  会被 gb18030 "成功" 解成乱码。这在不引入编码探测器的前提下无法可靠区分,
  所以凡兜底解码 (非 utf-8) 一律写进警告, 不静默; 确认是 Big5 源请先在源端转码。
- 表头仅 1 列且数据行恰好多 1 字段时, 按"单列 + 千分位"解释而非索引移位
  (金融场景下概率更高); 若确为 to_csv(index=True) 产物且只有 1 个命名列,
  请先在源端补上索引列名。
- **关掉全角开关后, 全角日期不会被识别**: 数值化路径会把全角 `１２３` 转成半角,
  但日期路径不做全角翻译, 所以关掉时 `２０２３．１．８` 按"解析失败"保留原值。
  默认开着时没这个问题 (整表先转半角, 日期识别自然接得住)。
- **默认会改写文本列的全角字符**: 名称、备注里的 `（）`、`／`、全角字母数字都会变半角。
  这是"默认开"换来的代价, 所以界面上常驻提示、报告里计入 `fullwidth_cells`、
  任意一列可点锁豁免。若你希望默认完全不动文本, 把开关关掉即可 (内核层默认仍是不动)。
- **产出登记只认当前输出目录里那一份**: 换机器或手工搬动过输出目录时登记对不上,
  防自吞噬就退化成只剩"cleaned/ 子目录"这一条。此时把输出目录设到输入目录之外即可。
  输入树里其他目录的清单不当权威: 宁可重洗, 也不静默漏文件。
- **预览是样本口径**: 单元格级运算是 O(行x列), 预览默认只算前 500 行并在界面上
  标注"样本"; 正式运行处理全量行。列级改动数在预览里是样本内的数量, 不是全量;
  **列类型识别 (标识符/日期) 同样只基于样本**: 前 500 行没有前导零、后面才有的列,
  预览会标成数值列而正式运行整列保留。样本口径下界面会常驻一条警告说明这一点。
- **xlsx 里的超大整数按文本写**: Excel 数值单元格是 float64, `|int| >= 2^53`
  的格子直接写数值会被舍入, 所以改成文本写出 (csv 不受影响, 全程精确)。
- **超过 2^53 的小数按"解析失败"保留原值**: float64 在这个量级连整数部分都放不下
  (相邻间隔 > 1), 强转 float 会舍入整数位、输出还变成科学计数法。纯整数不受影响
  (int 全程精确), 带小数的超大数值宁可不数值化, 也不静默改写。
- **SSE 重放窗口是 1024 条事件** (缓冲本身 2 万条): 重连拿到的是**最近** 1024 条,
  不够的部分会发一条 `replay_gap` 让界面明说"只覆盖窗口内"。每文件 3 个事件,
  所以一次批次约 340 个文件之内重连是无损的, 超过就会有缺口标记 —— 这是显式退化,
  不是以前那种"回放最旧 1024 条、job_end 必然拿不到、进度条永远转圈"。
- **时间拆列会多出一列**: 含时间分量的列变成 `列名` (只留日期) + `列名_时间` (HH:MM:SS),
  列数因此增加; 原表没有该列, 界面上标成"新增列"。没有该列名冲突时后缀固定 `_时间`,
  撞名会加序号。不想多一列就把这些值先在源端拆好, 或关掉日期统一。
- **分组不合规的写法保留原文本**: `1.234,5` / `1,23` 这类格子不会被数值化, 于是那一列
  可能出现"数值与文本混排"。这是取舍: 逗号在金融数据里既可能是千分位也可能是欧式小数点,
  猜错的代价 (差一千倍) 比不猜大得多。
- **写法碰撞只警告不改数值**: `2023.1` 与 `2023.10` 同在一列时会留痕, 但仍然照洗;
  真要保住写法请点锁保护那一列。
- **Excel 里以"数值 + 零填充格式"存的代码救不回来**: 单元格里躺的就是数字 1,
  `dtype=object` 只能保住以文本存储的 `000001`。这类源文件请在 Excel 里改成文本列再导。
- **无表头的文件第一行会被当成列名**: 本工具按"表头 + 数据"读, 没有"无表头"选项;
  纯数据文件请先补一行表头, 否则少一行且列名变成一个数据值。
- **界面上的单元格文本截到 160 字符**: 只是显示截断, 改动判定用完整文本
  (以前用截断串比, 尾部的改动会被算成"无改动")。
- **本地 API 对同用户进程不设防**: 守卫只挡浏览器 (Host 回环 + Origin 同源),
  不挡本机其他程序 —— 没有会话令牌, 同用户的进程可以直接读任意 `.txt/.csv` 内容、
  枚举目录、往任意可写目录写文件。这对单用户桌面工具是可接受的残余风险,
  但别把它当成"只服务本机界面"的安全边界。
- **本地 API 只服务回环**: 不放开 CORS, Host/Origin 非本机一律 403
  (生产同源, `--dev` 走 vite proxy, 都不需要跨源); 这同时挡掉 DNS rebinding。
- **拖拽上传同名不覆盖**: 落盘时同名自动加序号, 与输出端的防覆盖立场一致。
